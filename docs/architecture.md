# Архитектура сайта denisyuce.com

## Основной принцип

Сайт — статическая сборка Astro. GitHub Pages получает только готовую папку `dist`; исходные HTML-файлы и служебные данные в публикацию не попадают.

Единый дизайн собирается из компонентов `Header`, `Footer`, `ServicePriceList`, `ServicesGrid`, `Subscriptions`, `FAQ`, `Reviews` и `RelatedServices`. Новые общие блоки следует добавлять компонентами, а не копировать между страницами.

## Источники данных

1. DIKIDI синхронизируется внешним Cloudflare Worker и сохраняет проверенный снимок.
2. GitHub Actions читает снимок через `tools/sync-services-catalog.py`.
3. `assets/data/services-catalog.json` содержит факты DIKIDI: услуги, порядок, длительность, цену и ссылку записи.
4. `assets/data/services-presentation.json` содержит редакционные настройки сайта: объединение вариантов в одну страницу, адрес, тексты и изображения.
5. `tools/export-astro-data.py` проверяет оба файла через `services_catalog.py` и создаёт один типизированный снимок для Astro.

Astro никогда не обращается к DIKIDI во время просмотра страницы. При ошибке синхронизации остаётся последний корректный снимок, а проблема показывается в админке и уведомлениях.

## Страницы услуг

`src/pages/services/[slug].astro` автоматически создаёт страницу для каждого адреса из `services-presentation.json`. Поэтому новая услуга не требует ручного создания HTML-файла. Несколько вариантов длительности могут ссылаться на один `slug` и получают общие тексты страницы, но сохраняют отдельные цены и ссылки DIKIDI.

Прайс, карточки услуг и страницы используют один и тот же экспорт данных. Это исключает расхождение порядка, названий и цен.

## Остальные страницы

Ключевые коммерческие страницы (`/`, `/services/`, `/services/[slug]/`) написаны нативно на Astro. Большая существующая база мышц, конспектов, тестов и документов проходит через общий Astro-маршрут `src/pages/[...path].astro`: содержимое сохраняется, а шапка и подвал заменяются общими компонентами. Это позволяет мигрировать весь сайт одной сборкой без риска переписывания сотен стабильных материалов.

## Изображения и фиды

PNG-исходники услуг в `assets/source/services/` остаются единственным источником изображений. Папки `site/` и `catalog/` разделяют общие иллюстрации страниц и изображения конкретных вариантов услуги. `tools/convert-service-images.py` делает WebP в `assets/services/` для сайта, а `tools/generate-meta-services-feed.py` — PNG для внешних каталогов. Astro не дублирует эту обработку.

Фиды создаются Python-генераторами из того же проверенного каталога. Изображения, цены и описания сайта и фидов поэтому связаны с общими данными, но публикуются в форматах, нужных каждой площадке.

`tools/prepare-public-assets.py` создаёт игнорируемую Git папку `public/` перед локальным запуском и production-сборкой. В неё попадают только файлы, которые действительно должны быть доступны посетителю. Исходные PNG, настройки представления и снимок DIKIDI в публикацию не копируются. Astro сам переносит подготовленное содержимое `public/` в `dist`, поэтому локальная и GitHub-сборка используют один путь вместо отдельного ручного копирования после Astro.

## Порядок выпуска

1. Установить зависимости.
2. Конвертировать изображения.
3. Обновить и проверить снимок DIKIDI.
4. Сгенерировать фиды.
5. Собрать Astro в `dist`.
6. Сгенерировать sitemap из итоговых HTML.
7. Выполнить проверки и минификацию.
8. Опубликовать `dist` атомарно через GitHub Pages.

Если любой шаг падает, новая версия не публикуется и рабочая версия сайта остаётся доступной.

## Админка

Админка изменяет `services-presentation.json` через GitHub и загружает PNG в `assets/source/services/`. Проверка существования ручного `services/<slug>/index.html` больше не нужна: Astro создаёт страницу из данных. Валидация безопасного адреса, обязательных текстов, изображений и единственного основного варианта остаётся на сервере.

Короткие ссылки админка продолжает создавать в `url/<slug>/index.html`. Динамический маршрут `src/pages/[...path].astro` читает эти файлы во время статической сборки, поэтому новая, изменённая или удалённая ссылка автоматически отражается в следующем деплое. Такие страницы остаются `noindex` и не попадают в sitemap.

## Локальная работа

- `npm run dev` — локальная разработка.
- `npm run build` — экспорт данных и полная статическая сборка.
- `npm run check` — проверка Astro и TypeScript.
- `python3 tools/test-services-catalog.py` — соответствие услуг и фидов.
- `python3 tools/test-astro-site.py` — сохранность маршрутов и общего макета.

`public/`, `dist/` и `src/generated/` являются производными папками и не редактируются вручную. `assets/Icon_Pack` не является частью новой сборки и не должен сканироваться или копироваться. Нужные иконки сайта хранятся непосредственно в компонентах или в явно используемых файлах.
